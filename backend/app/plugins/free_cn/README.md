# free_cn 新浪公开行情插件

使用后端已有的 httpx，无需额外依赖或 API Key。由现有 plugin.yaml 加载器发现，在设置页能力路由中独立选择。

## 数据集与边界

| 数据集 | 实现 | 边界 |
| --- | --- | --- |
| adj_factor | hfq.js 累积因子相邻比值，日线收盘配价 | 单事件 pre/post 因子；不缓存全市场历史日线 |
| realtime | Market_Center 分页枚举 A 股，hq.sinajs.cn 批量报价 | OHLCV、涨跌幅和时间来自同一报价；换手率来自 Market_Center；不覆盖 ETF 全市场快照 |
| minute | 新浪移动端 1m | 最多 1023 根，声明 4 个交易日；成交额为 null |
| depth5 | 新浪批量报价 | 保留五档和零数量空档；数量股÷100，保留零股；未知数量为 null |
| full_minute | get_intraday_batch 当日窗口 | 仅修复轮，不实现 get_intraday_latest |

不声明 daily 或 financial；这两项保持用户原有数据源。实时指数通过 get_realtime_indices 按需补拉，量、额口径未确认前保留 null。

## 标准化与失败行为

- 代码始终携带交易所；同码的沪深标的不会互相覆盖。
- 日线配价及分钟、实时成交量为手，成交额为元；盘口数量允许小数手。
- 实时 timestamp 来自报价中的北京时间 date + time，不能以抓取时间代替。无可信行情时间的报价不返回。
- change_pct 按同一报价的最新价和昨收推导为小数；换手率百分数显式除以 100。
- 分钟 datetime 为 naive 北京墙钟，按完整起止时间过滤；带时区的请求先转换为北京时间。超出上游深度的历史不承诺补齐，覆盖不足记告警。
- HTTP、JSON 或报价结构异常：实时返回 [] 并告警；指数返回 None 保留旧缓存；成功空指数响应返回 []。分钟和除权单标的失败记录告警并跳过，不跨源兜底。
- HTTP 客户端由 provider 持有，close() 释放资源。

## 限频与启用

Market_Center 页间隔 0.12 秒，报价批间隔 0.08 秒，日线/除权/分钟请求间隔 0.20 秒；同进程共享节流器。

全市场实时一轮包括枚举和报价两组分页请求，建议轮询间隔至少 60 秒。全市场分钟逐标的拉取可能需要十几至几十分钟；服务的 60 秒下限不是全市场完成时间承诺。

在设置页把除权、实时、分钟、五档、全量分钟的能力路由切到 free_cn 即可。选择路由不会自动开启实时行情或分钟任务。分钟历史积累复用项目现有同步和全量分钟服务，不依赖额外的归档服务或脚本。

4 日浅源在现有 1/5/10/20 日快捷档中仅开放 1 日档。已有落库历史不会被插件删除；回测仍需核对目标窗口的真实覆盖。

## 验证

在 backend 目录运行：

```bash
uv run --frozen pytest tests/test_free_cn_provider.py -q
uv run --frozen ruff check app/plugins/free_cn tests/test_free_cn_provider.py
```

测试使用假客户端及固定样本，无网络和 Key 依赖。真实上游可通过设置页各数据集的试拉验证；免费接口的可用性、覆盖范围和吞吐不作保证。
