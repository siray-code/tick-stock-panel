### #494 的最终行为

显式选择自定义 `minute` / `full_minute` 源后，插件卸载、能力缺失、请求失败和分钟时间戳校验失败都不会改请求 TickFlow。只有明确选择 TickFlow 才走其原生权限与取数路径。失效自定义源的指数分钟缓存键与 TickFlow 分开，避免切换来源时复用错误缓存。

在上游补丁基础上增加：

- `config.datasets` 损坏为 `None` / 非容器时，也在 resolver 内隔离错误；分钟和全量分钟都覆盖该失败路径。
- 分钟传输、分时监控和时区用例同时隔离持久化偏好与 getter，避免本机配置影响测试路由。
- 更新插件、自定义数据源和配置文档，移除分钟源失败后自动回退 TickFlow 的旧描述。

未改变 API 字段、流式协议、Parquet schema、价格或时间单位。本地分钟行情文件不重写、不迁移；源不可用时相应实时结果为空或能力不可用，需要恢复该源或显式改选来源。

两个异动用例使用应用的 `cn_today()` 构造缓存日期，并固定业务日期以独立于测试机器日期运行。只修改测试，不修改异动计算逻辑或阈值。

### #495 的适配差异

原 PR 在首次同步部分交易所失败时仍写入残表，已有表失败时返回 0。当前任务调用方会将普通返回视为同步成功，因此本 fork 改成以下语义：

- TickFlow 的每个交易所最多尝试 3 次，重试前等待 3 秒、6 秒；空响应与异常都视为失败并重试。
- 重试后仍有任一交易所失败时，抛出 `InstrumentSyncIncompleteError`，列出失败交易所；有旧表则逐字节保留，首次同步不创建残表。
- 盘前与盘后管道收到该异常后失败，不继续报告“维表同步完成”或使用残表推进后续步骤。
- 完整成功路径保留当前基线的 `_preserve_share_fields`、原子写入和缓存刷新调用链；自定义源维表分支不改路由规则。

`sync_instruments` 的正常返回仍为写入行数；不完整 TickFlow 同步现在是明确异常。未新增配置字段，也不需要迁移已有维表。
