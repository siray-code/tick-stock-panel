## 首次定制

本次按 [二开规范](secondary-development.md) 的 L3 管理：直接修改内置提示词，因为已有扩展接口不提供替换这些提示词的能力；不另建提示词框架或新增配置开关。

- 个股、财务、大盘复盘、概念/行业轮动和对话助手允许依据已有数据回答交易建议。
- 共用关注重点处理只规范化空白，不按买卖、仓位、止损止盈或目标价关键词强制改写问题。
- AI 报告与助手界面移除对应的“不构成投资建议”文案，保留数据日期、适用条件和风险提示。
- 继续保留数据真实性、字段单位、数据不足说明，以及助手动作确认、超时和拒绝处理。没有新增下单工具或自动交易能力。
- 项目通用引导页与回测页的使用声明不属于本次 AI 文案调整范围。

HTTP API、NDJSON/SSE 事件、数据源路由、行情计算、查询键和报告存储格式均未变化。此次影响的是新生成报告与新对话的提示词，不需要清理数据缓存或重算行情。

### 历史内容与自定义复盘模板

历史报告与聊天内容不自动重写。报告需重新生成后才使用新提示词；已有对话历史也可能包含旧回答，验证新行为建议新建会话。

用户保存过的自定义大盘复盘系统提示词仍优先于内置默认值，代码升级不会覆盖它。如果模板含旧版交易建议禁令，可在复盘系统提示词设置中手动编辑，或恢复默认后重新生成报告。所配置模型服务的自身行为也会影响最终输出；提示词测试验证的是应用发出的指令，不代表真实模型一定给出特定建议。

## 后续开发与上游升级

1. 开发前读取根目录 `CONTRIBUTING.md` 与 `docs/secondary-development.md`，先核对工作区修改和真实调用链。
2. 新页面、数据源、策略优先复用已存在的扩展接口；修改核心源码时保持单一目的，并覆盖对应数据、缓存和兼容契约。
3. 需要同步上游时先执行 `git fetch upstream --tags`，选择明确版本 Tag 或 commit，不自动合并持续变化的开发分支。
4. 将工作保存到经授权的提交后，运行 `python3 scripts/upgrade_check.py <目标Tag或提交>`。该预检不包含未提交内容，不能替代真实合并后的回归。
5. 对照 [上游 PR 评审](upstream-pr-review.md) 检查重复实现和依赖，优先提取目的单一的提交。CI 通过或 Git 无文本冲突都不能替代业务验证。

本次需要重点复核的升级位置是共用关注重点处理、四类报告提示词和助手系统提示词；上游修改这些位置时，应重新运行提示词契约与流式调用测试。
